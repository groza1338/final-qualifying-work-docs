# Терминология проекта

## Правила ведения терминологии

В этом документе ведётся контролируемая база терминов для проекта ВКР.

**Каноническая терминология**: один научный концепт = один предпочтительный
русский термин, если в проекте не определено иное.

**Синонимы**: допускаются только те варианты, которые фактически используются
в исходных текстах, стандартах или распространённой технической практике.

**Одна концепция, один термин**: один и тот же концепт должен обозначаться
одним и тем же каноническим термином во всей документации.

**Устаревшие термины**: термины, которые больше не используются в проекте,
удаляются из активной базы. История изменений хранится в Git-коммитах.

**История изменений**: все изменения терминологии фиксируются в Git как
отдельные атомарные коммиты с сообщениями вида:
```
agent(terminology-guardian): add term "компонент системы" for architecture chapter consistency
```

## Активные термины

### Backend-модуль

- **Статус:** active
- **Краткое определение:** серверная часть системы, обеспечивающая передачу данных между мини-приложением Telegram, ботом и CRM-системой.
- **Расширенное пояснение:** backend-модуль принимает HTTP-запросы клиентского приложения, выполняет аутентификацию пользователя, хранит локальное состояние, обращается к внешней CRM-системе и преобразует ответы в формат, пригодный для фронтенда.
- **Допустимые варианты:** серверный модуль, backend-приложение
- **Недопустимые варианты:** бэкенд как самостоятельный термин в академическом тексте, серверная часть без уточнения роли
- **Связанные термины:** серверный интеграционный слой, HTTP API, CRM-система, мини-приложение Telegram
- **Контекст использования:** при описании разработанного программного результата и его архитектуры.
- **Пример корректного употребления:** «Backend-модуль выполняет проверку сессии и обращается к CRM-системе через адаптер».
- **Дата добавления:** 2026-06-07
- **Последняя проверка:** 2026-06-07

### CRM API

- **Статус:** active
- **Краткое определение:** программный интерфейс внешней CRM-системы, через который backend-модуль получает и изменяет бизнес-данные салона.
- **Расширенное пояснение:** CRM API используется для получения сведений о салоне, услугах, мастерах, расписании и записях, а также для создания, переноса, подтверждения и отмены записей.
- **Допустимые варианты:** API CRM, интерфейс CRM-системы
- **Недопустимые варианты:** CRM-интерфейс без уточнения программного характера
- **Связанные термины:** CRM-система, CRM-адаптер, HTTP API
- **Контекст использования:** при описании интеграции с внешней системой и преобразования данных.
- **Пример корректного употребления:** «CRM API является внешним источником данных о расписании и записях клиентов».
- **Дата добавления:** 2026-06-07
- **Последняя проверка:** 2026-06-07

### CRM-адаптер

- **Статус:** active
- **Краткое определение:** компонент backend-модуля, скрывающий особенности внешнего CRM API от прикладных сервисов.
- **Расширенное пояснение:** CRM-адаптер формирует запросы к CRM, проверяет ответы, преобразует внешние структуры данных во внутренние схемы и передаёт прикладному слою доменные ошибки.
- **Допустимые варианты:** адаптер CRM
- **Недопустимые варианты:** CRM-клиент как полная замена термина, если речь идёт не только о низкоуровневом HTTP-обмене
- **Связанные термины:** CRM API, прикладной сервис, серверный интеграционный слой
- **Контекст использования:** при описании слоя интеграции с внешней CRM-системой.
- **Пример корректного употребления:** «CRM-адаптер преобразует ответ внешней системы в схему ответа backend-модуля».
- **Дата добавления:** 2026-06-07
- **Последняя проверка:** 2026-06-07

### CRM-система

- **Статус:** active
- **Краткое определение:** внешняя информационная система салона, предназначенная для хранения клиентских данных, услуг, расписания и записей.
- **Расширенное пояснение:** в рамках работы CRM-система рассматривается как основной источник бизнес-данных и как система, в которой фиксируются изменения записей клиентов.
- **Допустимые варианты:** внешняя CRM-система
- **Недопустимые варианты:** ЦРМ, CRM без слова «система» при первом употреблении в разделе
- **Связанные термины:** CRM API, клиент CRM, запись клиента
- **Контекст использования:** при описании предметной области, внешних интеграций и границ ответственности разработанного модуля.
- **Пример корректного употребления:** «CRM-система хранит данные о мастерах, услугах и расписании салона».

### Redis Stream

- **Статус:** active
- **Краткое определение:** структура данных Redis, используемая в проекте для публикации уведомлений на последующую обработку ботом.
- **Расширенное пояснение:** Redis Stream отделяет приём запроса на отправку уведомления от фактической доставки сообщения пользователю через внешний канал.
- **Допустимые варианты:** поток Redis
- **Недопустимые варианты:** очередь Redis как полная замена термина, если важно указать используемую структуру данных

- **Пример корректного употребления:** «Backend-модуль публикует сообщение в Redis Stream для дальнейшей отправки пользователю».
